Xenia Nessuvia

A local-first character chat and story-writing app. No install, no account, no server holding your data.

Open the app

Summary

Xenia Nessuvia is a static web app for chatting with character cards, writing long-form stories against the same characters, and running multiplayer sessions that guests join from a link. It talks to any OpenAI-compatible model endpoint using an API key you supply. Nothing goes through an account and no database of ours holds any of it. The source is GPL v3.

Chat

Imports TavernV2 character cards, or build one in the editor. Alternate greetings and swipes work as expected. Each character can carry its own text color, so a multi-character chat stays readable at a glance. Characters can carry a gallery of linked images beyond the main avatar. World info entries trigger on keywords in the conversation and inject their text into the prompt when they match. Lorebook control is intentionally simple today.

Before it reaches the screen, model output passes through the grammar hammer: a rules pass that strips repeated tics and cleans up formatting. It only touches what's displayed; the stored message is the model's raw text. For more involved cleanup, Second Pass lets you run your own post-processing rules over model output without changing what gets saved.

Write

Write is the long-form counterpart to Chat, and it works on a different model: chapters built from beats with word targets, rather than a back-and-forth. It shares characters and world info with Chat, but the structure underneath is its own.

Multiplayer

The host starts a session and shares a link. Guests join with a persona, no install or account. Turn order is rearrangeable. A narrator role answers when no character present should. Only the host holds an API key, and only the host talks to the model.

Ask

A single question to the model, outside any chat, with an optional character loaded to answer as.

Prompts

Prompt content is built from reusable, rearrangeable blocks. Blocks support XML-style tagging. One block type is a scroll: a single number, like a target word count, adjusted directly without opening the block. A live prompt preview shows the assembled text before it is sent, and Chat includes a raw request inspector so you can see the exact payload reaching the endpoint.

Palette

Appearance is its own system: built-in webfont loading, app-wide color palettes, and panel styling, plus scoped custom CSS and HTML for backgrounds. Custom CSS is wrapped in @scope so it can't leak into the rest of the app.

Models and settings

Endpoints
Any OpenAI-compatible endpoint, hosted or on localhost. Chat completion and text completion both work.
Samplers
Sampler parameters are rows of data. Add one by hand for a backend-specific parameter Xenia doesn't already list, and it appears in the UI. That includes local-backend samplers like Mirostat, Min-P, DRY, or quadratic sampling without waiting for a release.
Import and export
A single JSON file holds characters, chats, stories, and settings, and reloads on another machine. API keys and bucket credentials are stripped from that file before it's written.

Where data goes

Characters, chats, stories, and settings sit in the browser's IndexedDB. Four things leave the tab, and nothing else does:

  • Model requests go to the endpoint you configure, with your own API key.
  • Multiplayer messages pass through a relay (Supabase Realtime, or a self-hosted Centrifugo instance) that stores nothing and never sees API keys.
  • Sync, if turned on, writes records to an S3-compatible bucket you own.
  • A tokenizer vocabulary downloads from jsDelivr, only when requested, with no user text sent.

Requirements

A modern browser and an API key for an OpenAI-compatible endpoint. Nothing else to install; the app can be added to a home screen or desktop as a PWA.

Status

Free to use, no signup. Actively developed and used daily by its author. Source at github.com/nessuvia/xenia-nessuvia.
